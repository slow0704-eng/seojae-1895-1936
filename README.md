## 서재에서 고르기

**찾기**는 제목(영문·한글), 원제, 작가, 연도, 연대, 형식을 한꺼번에 봅니다.
띄어쓴 낱말은 모두 만족해야 하고, **초성만 쳐도 걸립니다** — `ㅇㄷㅎ ㄱㅊㅂ` 로
『위대한 개츠비』가, `ㅋㅍㅋ` 로 카프카 7편이 나옵니다. 입력 중에는 상위 8편이
바로 아래 목록으로 뜨고 `↑` `↓` `Enter` 로 곧장 펼칠 수 있습니다.

**작가 바**는 검색창 아래에 늘 떠 있습니다. 작가 이름을 누르면 그 작가의 책만 남고,
한 번 더 누르거나 `전체`를 누르면 풀립니다. 거르기의 작가 항목과 같은 조건이라 다른
조건과 함께 걸립니다.

**거르기**는 여섯 갈래입니다 — 작가 · 연대 · 형식(장편/단편집/단편/희곡/…) ·
분량(3시간 이내 / 3–8시간 / 8시간 이상) · 상태(안 읽음/읽는 중/완독/책갈피 있음) ·
언어(한글본 있음/완역/원문만). 같은 갈래 안에서는 OR, 갈래끼리는 AND로 묶입니다.
고른 조건은 다음에 열 때도 남습니다. 걸러낸 결과 옆에는 **남은 편수와 총 독서 시간**이
같이 나옵니다.

**정렬**은 연대순 · 저자별 · 제목순 · 길이순 · 최근순 다섯 가지입니다.
저자별 화면에는 위에 작가 이동 막대가 붙고, 작가마다 전체 분량 · 완독 · 읽는 중 ·
한글본 편수 · 남은 시간이 표시됩니다.

## 한국어판

언어 버튼은 세 곳에 있습니다 — 한글본이 있는 책의 서재 카드 아래 **열기 영문 · 한글 · 대역**,
읽는 동안 늘 떠 있는 **왼쪽 아래 스위치**, 그리고 리더 위쪽 막대. 단축키 `l`은 셋을 차례로 돌립니다.

| | |
|---|---|
| **영문** | 원문 그대로 |
| **한글** | 본문 전체가 한국어. 아직 안 옮긴 문단은 원문으로 남고 `원문` 표가 붙습니다 |
| **대역** | 문단마다 원문 아래 번역이 붙습니다. 원문 크기는 70–100%로 조절 |

번역본은 **원문에 얹히는 층**입니다. `data/ko/<작품>.js` 가 영문 본문과 똑같은
문단 번호를 키로 삼아 한국어 문장을 들고 있고, 리더는 언어를 바꿀 때 그 번호로
같은 문단에 다시 내려앉습니다. 문단 안 위치는 두 언어의 글자 수 비로 환산합니다.
그래서 **45% 지점에서 한글로 바꿔도 45% 지점**이고, 책갈피와 목차 진도도 그대로입니다.

대역 모드의 번역 문단은 `data-p` 가 없는 **형제 문단**입니다. 글자 수 표와 저장된
비율이 영문과 완전히 같은 값으로 남기 때문에, 대역으로 읽다가 영문으로 돌아가도
진도가 흔들리지 않습니다.

장 제목도 함께 번역되어 목차·상단 표시·책갈피 목록에 한국어로 나옵니다.

부분 번역된 작품은 표지에 `한 78%` 같은 배지가, 속표지에 `번역 78% · 나머지는
원문으로 표시됩니다` 가 붙습니다. 완역이면 `한` 만 붙습니다.

### 번역을 이어서 채우기

절차·노트 쓰는 법·병렬 번역 뒤 맞출 것·저작권 기준은 **[번역가이드.md](번역가이드.md)**, 문체 규칙은 [tools/tr/GUIDE.md](tools/tr/GUIDE.md).

```bash
cd tools
python translate.py status                 # 작품별 진행률
python translate.py plan --tier1           # 작업 단위(7,000자)로 쪼개기
python translate.py todo 20                # 아직 안 채운 작업 20개
#   → 각 작업 파일을 번역해 tools/tr/out/<작품>/NNN.json 으로 저장
python translate.py build --all            # out/*.json → data/ko/*.js + index.js
```

작업 단위는 문단을 쪼개지 않고, 장 제목에서 새로 시작합니다. 각 작업 파일에는 앞
문단의 끝부분이 문맥으로 들어갑니다. 여러 사람(또는 여러 에이전트)이 같은 책을 나눠
맡아도 인물 이름과 말투가 갈라지지 않도록, 공통 지침 `tr/GUIDE.md` 와 작품별 표기
노트 `tr/notes/<작품>.md` 가 이름·경어법·고유명사를 미리 못박아 둡니다.

`build` 는 검사를 통과한 것만 싣습니다 — 키가 원문에 없거나, 빠졌거나, `<em>` 이
짝이 안 맞거나, 한글이 한 글자도 없으면 그 문단은 버리고 원문을 그대로 둡니다.
그래서 번역이 덜 끝난 책도 언제든 읽을 수 있는 상태입니다.

## 설계 결정

읽는 데 실제로 영향을 주는 것들만 적습니다.

**위치 저장은 스크롤 오프셋이 아니라 `(문단 번호, 문자 오프셋)` 앵커.**
DOM `Range`로 픽셀 위치를 역산하므로 글자 크기·창 너비·서체를 바꿔도
읽던 **글자**가 같은 자리에 남습니다. 화면 18% 지점을 기준선으로 삼아
돌아왔을 때 앞 문맥이 두어 줄 보이도록 했습니다.

**본문 너비는 `em` 기준.**
`ch`는 숫자 `0`의 폭이라 Sitka에서 66ch는 실제 77자가 됩니다. 서체별 실측
평균 자폭(Sitka 0.4709em / Constantia 0.4328em / Georgia 0.4390em)으로 계산해,
어떤 크기·서체에서도 **한 줄 글자 수가 고정**됩니다.

**본문 서체는 Sitka Text.**
Windows에 실제로 설치된 본문 세리프 중 `gasp` 테이블상 16–22px 전 구간에서
DirectWrite의 symmetric 렌더링을 타는 유일한 폰트입니다(Georgia는 19px부터,
Constantia는 23px부터, Palatino Linotype은 어느 크기에서도 안 탐). x/cap 비율
0.756으로 대문자가 조용하고, 기본 숫자가 올드스타일이라 `1895` 같은 연도가
본문 색조에 묻힙니다.

**양쪽 정렬 없음.** Chrome에는 Knuth–Plass 문단 최적화가 없어 72자 폭에서
강물자국이 생깁니다. 게다가 독자가 폭을 바꿀 수 있으므로 조판자가 폭을 고정하고
검수하는 전제가 성립하지 않습니다.

**단락 사이 여백 대신 첫 줄 들여쓰기.** 웰스와 피츠제럴드는 화자마다 줄을 바꿔서,
여백 방식으로 조판하면 대화 장면이 글이 아니라 목록처럼 보입니다.

**순백·순흑 없음.** 본문 대비는 종이 14.0:1, 세피아 12.3:1, 야간 11.6:1, 심야 8.0:1.
인쇄된 책의 대비(12–15:1) 대역에 맞췄습니다. 다크 테마의 헤일레이션(글자 번짐)은
흰색 대신 L 86%/72% 난색 회색을 써서 글자당 발광량을 37%/64% 낮추는 방식으로
잡았습니다. 강조색은 매더 레드 계열 — 사본 채식과 책 스파인의 색이지, 대시보드 색이 아닙니다.

**장 단위 `content-visibility`.** 124만 자짜리 『조앤과 피터』도 첫 화면이 즉시 뜹니다.
문단 단위가 아니라 장 단위인 것은 스크롤 높이 추정 오차를 줄이기 위해서고,
Chrome의 `Ctrl+F`가 여전히 안쪽을 찾습니다.

**페이지 넘김 모드 없음.** 재조판 비용, `Ctrl+F` 파손, 선택 영역 끊김,
앵커 복원 난이도에 비해 얻는 게 적습니다. 스크롤 + 2줄 겹침으로 대체했습니다.

### 왜 한 페이지인가

처음에는 작품마다 HTML 한 개씩, 총 61개 파일로 만들었습니다. 그런데 **현재 Chrome은
`file://`에서 파일별로 `localStorage`를 분리합니다** — 실측으로 확인했습니다. 그래서
서재 페이지가 다른 작품의 진도를 읽을 수 없었습니다.

`file://`에서 `fetch()`는 막히지만 동적으로 붙인 `<script src>`는 동작합니다. 그래서
본문을 `data/<작품>.js`로 내보내고, 클릭하는 순간 스크립트 태그로 주입합니다. 문서도
오리진도 하나뿐이라 저장소 문제가 통째로 사라지고, 페이지 새로고침 없이 책이 열립니다.

주소는 `#/w/<작품>` 해시로 관리하므로 브라우저 뒤로/앞으로가 그대로 동작합니다.
`history.scrollRestoration`은 `manual`로 둡니다 — 브라우저의 스크롤 복원이 앵커 복원
뒤에 도착해 저장된 진도를 0%로 덮어쓰는 일이 실제로 있었습니다.

또 하나의 불변식: **책을 열고 손대지 않았다면 아무것도 기록하지 않습니다.**
실수로 펼쳐본 것이 읽던 위치를 지우면 안 되기 때문입니다.

백업이 필요하면 설정의 **내보내기/가져오기**(JSON)를 쓰면 됩니다.

번역이라면서 한글이 없는 문단이 없는지, `index.js` 의 진행률이 최신인지.

### 파싱이 어려웠던 부분

목차(CONTENTS) 블록을 먼저 수집해 **책 자신의 목차를 정답으로** 씁니다.
대문자 줄의 생김새만으로 제목을 판별하면 반드시 오검출이 납니다 —
고함치는 대사, 신문 헤드라인, 편지 서명, 작중 원고 제목이 전부 걸립니다.

버린 블록은 길이가 아니라 **텍스트 자체**를 기록해서, "뭔가 사라졌나?"를
정확한 등식으로 만들었습니다. 이 검사가 개발 중에 세 가지 실제 결함을 잡았습니다:
목차 수집기가 15개 파일의 1장을 삼킨 것, 스몰캡 정규식이 30개 파일에서
`&amp;amp;`를 쪼갠 것, 1장 제목이 조직적으로 누락된 것.
