# 낭독 작업 지침 — 서재 1895—1936

낭독(책 읽어주기)을 고치거나 넓힐 때 먼저 읽는 문서입니다. 전체 구조, 파일마다 어디를
고치는지, 작업 종류별 절차, 지금 남은 빈칸을 적습니다. 세부는 두 문서에 있습니다.

- 연기 대본(누가·어떻게 말하나)의 형식과 판단 기준 → [`tools/act/GUIDE.md`](../act/GUIDE.md)
- 합성 수치(모델·단계·속도·라우드니스·EQ·쉼)의 측정 근거 → [`CALIB.md`](CALIB.md)

## 1. 원칙

1. **기기 안에서.** 합성은 브라우저 워커에서만 합니다. 글을 밖으로 보내는 서버 TTS 를 붙이지 않습니다.
2. **본문을 건드리지 않습니다.** 읽는 자리 표시는 CSS Custom Highlight 로만 칠합니다. 정규화·읽기 치환·대본 모두
   **읽을 글자**만 바꾸고, 보이는 글자와 `data-p` 위치 계산은 그대로 둡니다.
3. **위치는 문단 번호와 순번.** 대본·요미는 글자 오프셋이 아니라 `data-p`(+ 문단 안 대사 순번,
   또는 그 문단의 화면 글자 위치)에 겁니다. 원문·한국어판·대역이 같은 자료를 함께 씁니다.
4. **측정한 값만 고정.** `config.json` 의 숫자는 CALIB.md 에 근거가 있어야 합니다. 귀로 정한
   값(쉼, 연기 매개변수)은 "첫 후보"라고 적어 두고, 들어 보고 고친 근거를 남깁니다.
5. **절제.** 낭독은 배우가 아니라 낭독자입니다. 연기는 본문 지문에 근거가 있을 때만, 절반 세기로.
6. **자료가 없으면 물러납니다.** 대본이 없거나 맞지 않으면 서술 목소리로, 신경망을 못 쓰면 기기 음성으로.
   어느 단계가 빠져도 읽기는 계속됩니다.

## 2. 구조 — 문단에서 소리까지

```
화면 #book (h2, p[data-p], 대역의 번역 문단)
  │ nrBuildBlocks   읽을 언어 고르기(보이는 쪽 / 대역이면 설정) → 블록 목록 {el, lang, kind, p}
  │ nrTokens        보이는 글자 ↔ 읽을 글자 토큰 (루비는 후리가나로 읽음)
  │ + 요미          일본어 원작: data/yomi/<id>.js 의 읽기로 한자 낱말 치환
  │ TTSNorm.sentences  문장 나누기 (긴 문장은 쉼표에서)
  │ nrActCut        대본이 있으면 대사 경계에서 다시 잘라 조각마다 {목소리, how, mood}
  ▼
조각(seg) ── nrPump: aheadSec 만큼 앞서 요청, 최근 소리는 캐시(nrKey)
  │
  ├ neural  worker.js (×maxWorkers) : 정규화 → 길이 예측 → 텍스트 인코딩 → 흐름 정합(steps)
  │                                    → 보코더 → 라우드니스(−21 LUFS ±3) → 무음 다듬기 → PCM
  │                                    WebGPU fp16 / fp32 · WASM int8 — 기기 보고 자동, 실패하면 아래로
  └ system  speechSynthesis (목소리 고정, 빠르기·높이만)
  ▼
Web Audio 그래프 : 목소리별 EQ → 압축 → 천장 → 방 울림 → (배경 소리) → 출력
  nrGap 이 구두점·문단·장 경계·대사 경계에 따라 쉼을 실제 시계로 예약 → 끊김 없이
  ▼
nrShow : 읽는 문장 밑줄 · 화면 따라가기 · 진도 저장 · 잠금 화면 미디어 단추
```

## 3. 파일 지도 — 어디를 고치나

**`서재/` 아래는 손으로 고치지 않습니다.** 모두 `tools/` 에서 만들어집니다.

| 원본 (고치는 곳) | 만드는 것 | 명령 |
|---|---|---|
| `tools/narrate.js` (런타임 전체) + `tools/act/spans.js` (대사 세기) | `서재/index.html` 안에 박힘 | `python tools/build.py` |
| `tools/tts/config.json` (모든 수치) | `NR_CFG` 로 index.html 에 박힘, `ver` = 워커 캐시 버전 | `python tools/build.py` |
| `tools/tts/worker.js`, `tools/tts/normalize.js` | `서재/tts/worker.js`, `normalize.js` | `python tools/build.py` |
| Supertonic 3 고정 리비전 | `서재/tts/voices.bin`, `indexer.bin`, `tts.json` / 큰 ONNX 는 URL·크기만 config 에 | `python tools/tts/pack.py` (모델 바꿀 때만) |
| 일본어 원문 `서재/data/<id>.js` | `서재/data/yomi/<id>.js` | `python tools/tts/yomi.py` (fugashi + unidic-lite 필요) |
| `tools/act/cast/<id>.json` + `tools/act/out/<id>/NNN.json` | `서재/data/act/<id>.js`, `index.js` | `python tools/act.py build <id>` |
| `tools/tts/calib/*` | CALIB.md 의 표 | `calib.py synth → asr → report`, `ltas.py` |

`tools/tts/act.js` — 대본 없는 책을 위한 **규칙 기반 화자·말투 분석기**. 지금은 빌드에도
런타임에도 연결되어 있지 않습니다(6절 ①).

## 4. 작업 종류별 절차

### A. 한국어판 완역이 하나 늘었을 때

낭독은 따로 할 일이 없습니다 — 번역 문단이 있으면 한국어로 읽습니다. 다만:

1. 번역 지침의 **따옴표 대사 수 지키기**가 대본 정렬의 전제입니다. 그 책에 대본이 있으면
   `python tools/act.py align <id>` 로 ko 일치율을 봅니다(목표 99% 이상, 물러난 문단은 번호를 확인).
2. 한국어 숫자·단위·호칭이 새로 나오면 B 로.

### B. 읽기 실수를 고칠 때 (숫자·단위·약어·기호)

1. 고칠 곳은 `tools/tts/normalize.js` 하나(워커와 node 가 같은 파일).
   한국어 수사(한자어/고유어), 영어 연도·서수·약어, 화폐(파운드·실링·펜스) 같은 규칙이 여기 있습니다.
2. node 로 문장을 직접 넣어 확인합니다:
   `node -e "const N=require('./tools/tts/normalize.js'); console.log(N.normalize('1906년 3펜스', 'ko'))"`
   (UMD — node 에서는 `module.exports`, 워커·브라우저에서는 전역 `TTSNorm`).
3. **보이는 글자 수를 바꾸는 처리는 정규화가 아니라 토큰 단계**에서 합니다 — 하이라이트 위치가 어긋납니다.
4. `python tools/build.py` 후 `?nrdebug` 로 그 문단을 들어 봅니다.

### C. 일본어 원작이 늘었을 때

`python tools/tts/yomi.py` → `서재/data/yomi/<id>.js` 를 커밋. 빌드는 표준 라이브러리만 쓰므로
이 단계는 따로 돌린 결과를 저장소에 둡니다. 원문을 다시 뽑으면(루비·문단이 바뀌면) 다시 돌립니다.

### D. 연기 대본을 새 책에 붙일 때

[`tools/act/GUIDE.md`](../act/GUIDE.md) 가 기준입니다. 순서만 요약:

1. **번역 노트**(`tools/tr/notes/<id>.md`)가 있어야 합니다 — 배역 이름이 여기서 옵니다.
2. 배역표 `tools/act/cast/<id>.json` 을 씁니다 → `python tools/act.py cast <id>` 가 `ok`.
3. `python tools/act.py plan <id>` → 작업 단위(`tools/act/jobs/`, gitignore).
4. **actor 에이전트**를 작업 하나에 하나씩. 앞 청크의 화자 흐름을 이어받으므로
   **001 을 먼저 끝내고**, 나머지는 몇 개씩 병렬로.
5. `python tools/act.py check <id>` → `build <id>` → `align <id>` (en/ko 모두).
6. 들어 보기: `?nrdebug`, 대화가 많은 장 하나를 처음부터. 화자가 틀린 곳은 대본(out)을 고치고 다시 build.
7. 커밋: cast · out · `서재/data/act/`.

**어느 책부터:** 대사 수가 많고 한국어판이 완역이며 짧은 책. 대사가 거의 없는 책(카프카 짧은 글,
『소송』처럼 대사가 긴 문단 속에 묻힌 책 — 1,488 대사가 81 문단)은 효과가 작으니 뒤로.
지금 후보 순서(대사 수 ÷ 분량): 『붉은 방』(62) · 『지옥변』(63) · 『별』(33) · 『라쇼몽』(15)
→ 중편 『삼촌과 나눈 대화』(324) · 『웬디고』(212) · 『버드나무』(232) · 『소녀 지옥』(492)
→ 장편은 대사 밀도가 높은 『놀라운 방문』(1,393) · 『바다 아가씨』(1,475) · 『위대한 개츠비』(1,458).

### E. 소리 값을 바꿀 때 (쉼·EQ·라우드니스·속도·연기 매개변수)

1. `tools/tts/config.json` 만 고칩니다. 코드에 숫자를 박지 않습니다.
2. 측정할 수 있는 값(명료도·라우드니스·스펙트럼)은 `calib/` 로 재고 CALIB.md 표를 고칩니다.
   측정할 수 없는 값(쉼, `act` 표)은 **같은 문단을 바꾸기 전·후로 들어 비교**하고, 무엇을 들었는지
   CALIB.md 또는 config 의 `_` 설명에 한 줄 남깁니다.
3. `python tools/build.py` — `ver` 가 바뀌어 워커·정규화 캐시가 새로 받힙니다.

### F. 모델·목소리를 바꿀 때

`pack.py` 의 `OFFICIAL` 리비전을 바꾸고 → `pack.py` → config 의 `cacheName` 을 올림(사용자 저장소의
옛 모델을 버리게) → CALIB 1·5·6 절을 다시 잽니다(목소리별 EQ·기본 목소리는 모델에 묶인 값).

## 5. 점검

- `?nrdebug` 로 리더를 열면 `window.NR_DEBUG` — 상태(`NR`), 설정(`S`), 수치(`cfg`).
  대본 조각: `NR_DEBUG.act(() => console.table(NR_DEBUG.segs(블록번호)))`.
- 커밋 전: `python tools/act.py check --all` · `python tools/act.py status` · 빌드 후 리더에서
  한국어판·원문·대역 각각 몇 문장 듣기, 일시정지/재개, 앞/다음 문장, 속도 ×1.5.
- `file://` 로 열면 워커를 못 띄워 기기 음성만 됩니다. 신경망은 로컬 서버(`python -m http.server`)로.

## 7. 하지 말 것

- `서재/index.html`, `서재/tts/*` 를 직접 고치기 (다음 빌드에 사라짐).
- 정규화에서 보이는 글자를 지우거나 늘리기 → 하이라이트·진도 위치가 어긋남.
- `act.py spans()` 와 `act/spans.js` 중 한쪽만 고치기 — 두 구현은 전 코퍼스에서 한 글자도 다르게 세면 안 됩니다.
  고치면 둘 다, 그리고 대본이 있는 모든 책을 `align` 으로 다시 셉니다.
- 근거 없는 `how`, 장면 분위기만 보고 모든 대사에 감정 걸기.
- 측정 없이 `steps`·`modelSpeed` 상한 올리기 — CALIB 3절에서 1.25 위는 발음이 무너집니다.
