# 낭독 캘리브레이션 — Supertonic 3

`tools/tts/config.json` 의 숫자가 어디서 왔는지 적어 둡니다. 측정 도구는 `calib/`
(`calib.py` · `ltas.py` · `bench.html`), 원자료는 `calib/asr.json` · `calib/ltas.json`.
측정일 2026-10-04 · 데스크톱(Ryzen 5 PRO 4650G, GTX 1050 2GB, Chromium) 한 대.

평가 문장은 이 서재의 실제 본문에서 뽑았습니다 — 한국어판 20문단(숫자가 든 문장 5개 포함),
영어 원문 12문단, 일본어 원문 9문단(`calib/samples.json`). 명료도는 Whisper large-v3-turbo
받아쓰기 오류율입니다. 한국어는 글자(CER), 영어는 낱말(WER), 일본어는 **가나로 바꾼 뒤의**
글자 오류율 — 한자 표기 차이(云う/言う)를 빼고 발음만 보려고.

---

## 1. 어떤 모델을 어디서 돌리나

### 브라우저 속도 (RTF = 합성 시간 ÷ 소리 길이, 12초 한국어 문장, 데운 뒤)

| 실행 | 모델 | steps | RTF |
|---|---|---|---|
| WASM 1스레드 | int8 (mobile VE + int8 보코더) | 6 | 1.6 (다른 측정과 CPU 경합) |
| WASM 1스레드 | 같음 | 5 | **0.66** (CPU 한가할 때) |
| WASM 6스레드 (COOP/COEP 필요) | 같음 | 6 | 0.77 |
| WebGPU | fp32 공식 | 8 | 0.09 |
| WebGPU, 잠재 변수 GPU 상주 | fp32 공식 | 8 | **0.08** |
| WebGPU | fp16 | — | GTX 1050(Pascal)에는 `shader-f16` 이 없어 실행 불가 |

- GitHub Pages 는 COOP/COEP 머리말을 못 붙여 WASM 멀티스레드를 쓸 수 없습니다. 대신 문장이
  서로 독립이라 **1스레드 일꾼을 여럿** 두는 쪽이 같은 효과입니다(`maxWorkers: 2`, 적응형).
- WebGPU 는 텐서 모양이 바뀔 때마다 셰이더를 새로 만들어 첫 몇 문장이 RTF 0.5–1.2 로 튑니다.
  입력 길이를 칸(32/16 배수)으로 올려 맞추고 빈 칸을 마스크 0 으로 채웁니다(배치 추론과 같은 방식).
  칸 맞춤이 소리를 바꾸는 정도는 잡음 씨앗을 바꾸는 것의 ⅓ 수준이고(멜 거리 0.44 대 1.36),
  명료도는 그대로입니다(한국어 CER 3.1% → 2.1%).

→ **프로필**: `shader-f16` 이 있는 GPU 는 fp16(190MB), 없는 GPU 는 fp32(380MB),
WebGPU 가 없으면 WASM int8(127MB). GPU 가 막히면 CPU 로 내려가고 반나절 동안 기억합니다.

### 양자화·단계별 명료도 (목소리 F1)

| 모델 | steps | 한국어 CER | 영어 WER | 일본어 가나 CER | fp32@8 대비 멜 거리 |
|---|---|---|---|---|---|
| fp32 | 8 | 3.1 | 1.7 | 11.6 | 0 |
| fp32 | 6 | 2.7 | 1.5 | 12.7 | 0.33–0.44 |
| fp32 | 4 | 4.1 | 2.4 | 13.3 | 0.80–0.92 |
| fp16 | 6 | 2.8 | 1.7 | 13.8 | 0.37–1.0 |
| int8 mobile VE + int8 보코더 | 8 | 2.9 | 3.2 | 15.4 | 0.87–1.0 |
| 같음 | 6 | 3.0 | 2.9 | 15.2 | 0.86–0.97 |
| 같음 | 4 | 3.4 | 4.2 | 17.5 | 1.0–1.1 |
| int8 VE + fp32 보코더 | 8 | 2.8 | 2.9 | 15.0 | 0.85–1.0 |
| sherpa int8 VE | 6 | 2.7 | 2.0 | 12.2 | 0.53–0.63 |

- fp16 은 fp32 와 구별되지 않습니다 → GPU 는 fp16 우선.
- 6 단계와 8 단계는 명료도 차이가 표본 오차 안이고, 4 단계부터 나빠집니다.
  GPU 는 싸니 **8**, CPU 는 **5**(적응형 하한 4).
- CPU 용으로는 sherpa int8 VE 가 fp32 에 더 가깝지만 mobile VE 가 두 배 빠릅니다(같은 조건 RTF
  0.61 대 1.21). 실시간이 먼저라 mobile. 보코더를 fp32 로 바꿔도 명료도 이득이 없어 int8 유지.

## 2. 일본어 — 한자 읽기

Supertonic 은 글자 단위 모델이라 한자를 '보고' 읽습니다. 옛 소설에서 틀린 예:
乞食→こしょく(こじき), 梯子→たんし(はしご), 云う→うん(いう), 蹲って→あたって(うずくまって).
`yomi.py` 가 MeCab + UniDic 으로 문맥에 맞는 읽기를 미리 구해 두고, 낭독 때 한자 낱말만
히라가나로 바꿔 넘깁니다(후리가나가 있는 곳은 원문 읽기 그대로).

| | 가나 CER |
|---|---|
| 원문 그대로 | 11.6% |
| 읽기 치환 | **6.2%** |

남은 오류의 상당 부분은 채점 쪽(pykakasi 의 기준 읽기, Whisper)입니다.

## 3. 속도

모델의 `speed`(길이 예측을 나누는 값)만으로 빠르기를 올리면 1.25 를 넘어서 무너집니다.

| speed | 한국어 CER | 영어 WER | 일본어 가나 CER |
|---|---|---|---|
| 0.8 | 3.5 | 3.1 | 18.4 |
| 1.05 | 1.9 | 3.1 | 13.0 |
| 1.25 | 1.2 | 3.1 | 13.2 |
| 1.5 | 11.7 | 3.1 | 23.4 |
| 1.75 | 43.2 | 17.8 | 39.7 |
| **모델 1.2 + WSOLA → 1.5** | **1.9** | 3.1 | 14.9 |
| **모델 1.2 + WSOLA → 1.75** | **1.6** | 3.1 | 15.1 |

→ 모델 속도는 `modelSpeed: [0.9, 1.2]` 안에서만 쓰고, 나머지는 음높이를 지키는 시간
늘이기·줄이기(WSOLA, 40ms 창 · ±12ms 탐색)로. 그래서 ×1.75 까지 엽니다.

### 기본 말 속도

speed 1.0 에서 잰 말 속도와, 낭독 관행에 맞춘 기본값(`speedBase`):

| | speed 1.0 | 기본값 | 결과 |
|---|---|---|---|
| 한국어 | 분당 303음절 | 0.97 | 약 295음절 |
| 영어 | 분당 170단어 | 0.92 | 약 155단어 (오디오북 통상 150–160) |
| 일본어 | 분당 310자 | 0.97 | 약 300자 (방송 낭독 기준치) |

## 4. 라우드니스

| | 통합 라우드니스 |
|---|---|
| fp32 / fp16 / 칸 맞춤 | −25.5 / −25.4 / −25.5 LUFS |
| int8 | −27.3 LUFS (−1.8 dB) |
| 문장 사이 표준편차 | 0.4–0.6 LU |
| 목소리 사이 | −24.0 (M2) – −25.6 (F2) |

문장마다 크기가 이미 고르므로 문장별로 크게 고치지 않습니다. 목소리·프로필별 평균
(`loud`)으로 기준 이득을 정해 **−21 LUFS** 에 맞추고, 문장별 보정은 ±3 dB 안에서만 —
속삭임과 외침의 차이는 남깁니다. 첨두는 −2 dBFS 아래로 묶고, 뒤에 압축기(2.2:1)와
소프트 천장(PULSE·16 의 `mkCeiling` 커브)을 둡니다.

## 7. 쉼

문장 사이 실제 간격 = 앞뒤 다듬은 무음(20ms + 60ms) + 아래 값 ÷ 재생 속도.

| 자리 | 초 |
|---|---|
| 긴 문장을 쉼표에서 나눈 곳 | 0.15 |
| 문장 끝 | 0.45 |
| 물음·느낌표 | 0.50 |
| 말줄임 | 0.65 |
| 문단 끝 | 0.85 |
| 장 제목 뒤 / 장 끝 | 1.2 / 1.8 |
| 대사가 열리거나 닫히는 자리 | +0.12 |

이 값은 받아쓰기로 잴 수 없는 영역이라 사람 낭독의 통상 범위에서 정했습니다 —
귀로 듣고 고칠 첫 후보입니다.
